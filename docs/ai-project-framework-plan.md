# AI 建立項目框架（待開發）

> **狀態：暫緩。** 2026-09-19 與產品討論後先記存，**不現在開發**。之後有空再依本文件重開確認與實作。

## 背景與目標

使用者在 AI 入口輸入項目描述，例如：

> 香港中環街市啤酒節，我們的工作範圍搭建兩個帳篷，並委託分判商完成此類工作，請幫我建立項目及其相關分類及分工。

系統應把描述拆成**最簡單的項目管理框架**：

- 項目（Project）
- 大類 → 第二層分工（現有 `ProjectSection`，最多兩層）
- 事項（`ProjectTask`：標題、內容等）

目的：用自然語言快速得到可改的骨架，再人工確認後寫入本系統 Projects 插件。

## 明確不做（本計劃範圍外）

- 自動指派分判／建臨時帳／授權
- 讀圖則、合約、附件再分析
- 自動排期／提醒策略
- 自動產生 PDF
- AI 直接寫庫、不可預覽

## 建議產品形態（已討論共識方向）

1. 入口：項目相關 UI 的「AI 建立框架」（權限待確認）
2. 輸入：多行描述（必填）
3. 後端呼叫 LLM → **嚴格 JSON schema** 草稿
4. **預覽＋可編輯**（改名、刪節點、加事項；強制 ≤2 層）
5. 使用者**確認後**才呼叫現有 `createProject` / `createProjectSection` / `createProjectTask`
6. 原則：**AI 只產草稿，寫庫必須人確認**

## 與現有資料模型對齊

| 現有 | AI 草稿對應 |
|------|-------------|
| `Project` | 標題、說明、狀態建議 |
| `ProjectSection`（root → child） | 大類 → 下級 |
| `ProjectTask`（`title` / `content` / `dueDate`） | 事項標題＋內容草稿；到期可留空 |
| 事項／分組附件 | 第 1 期可不由 AI 填 |

無需另造專案樹模型；難度主在 prompt／預覽 UX，不在 Prisma schema。

## 建議分期

### 第 1 期（MVP，之後優先）

- AI 入口＋描述 → 草稿預覽 → 確認建立
- 伺服器驗證：兩層上限、空標題、節點數量上限（建議：大類≤8、每層下級≤10、事項≤50）
- 事項 `dueDate` 預設可不填
- Admin／建立項目權限者可用（最終以確認項為準）
- API Key 僅伺服器；失敗有清楚錯誤

### 第 2 期

- 行業範本（活動搭建／街市／展覽）
- 「再生一版」、每日用量／費用上限
- 可選：建議負責人「角色名」文字（仍不自動建帳）

### 第 3 期（高難度，暫緩）

- 讀附件／圖則、對接分判、排期與文件包

## 技術備註

- 新 server actions 建議：`suggestProjectFramework`（只回草稿）、`commitProjectFramework`（確認後寫入）
- 輸出必須 schema 校驗，防 prompt 注入（只接受約定欄位）
- 可選：存模型名／草稿 JSON／提示摘要利於調校（注意個資）
- 系統已有項目 CRUD 與兩層分組；接 LLM 後映射即可

## 風險（已討論）

| 風險 | 對策 |
|------|------|
| 拆層亂、事項過多／過少 | 預覽必改＋數量上限 |
| 誤寫庫 | 僅 commit 寫入；validate |
| API 費用／金鑰 | 環境變數；可先限 Admin |
| 個資進模型 | 提示勿貼敏感個資；可關閉外呼 |
| Prompt 注入 | 只解析 schema |

## 難度結論（已對產品說明）

- **MVP（草稿預覽＋確認建立）：中低** — 合現有架構
- **品質穩定（建築／活動用語）：中** — 調校成本
- **讀檔／自動分判／排期：高** — 另案
